## Board layout

| List | Purpose |
|---|---|
| Product Backlog | All items, ordered by priority |
| Sprint Backlog | Items committed for this week |
| In Progress | Work I am doing now (limit: 2 cards) |
| Testing / Review | Built, waiting to be tested or demoed |
| Done | Accepted by my mentor |
| Blocked / Waiting | Items waiting on sign-off or someone else |

## Labels

| Colour | Meaning |
|---|---|
| Green | Feature |
| Blue | Technical |
| Red | Bug |
| Orange | Improvement from demo feedback |
| Purple | Future / won't now |

## Card format

- **Title:** the item ID and name (for example, `PB-09 Search`)
- **Description:** the user story
- **Checklist:** the tasks and acceptance criteria
- **Due date:** the sprint demo day

## Why Kanban alongside Scrum

The weekly sprints gave me a rhythm. The Kanban board gave me a visual view, so I could see at a glance what was in progress and what was waiting.
